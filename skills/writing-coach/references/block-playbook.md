# Writer's Block Playbook

Extended exercises for the block protocol in SKILL.md. Load this file when a
block intervention needs a guided exercise. Run ONE exercise per session —
the goal is momentum, not a workshop.

## Exercise index

| Block type | Exercise | Time |
|---|---|---|
| Blank page | Ugly sentence drill | 5 min |
| Blank page | Interview dump | 10 min |
| Blank page | 200 bad words | 15 min |
| Mid-draft stall | Casual-sentence probe | 5 min |
| Mid-draft stall | Rubber-duck the gap | 15 min |
| Mid-draft stall | Section veto test | 5 min |
| Perfectionism loop | No-backspace sprint | 25 min |
| Perfectionism loop | TK sweep | 10 min |
| Dread / avoidance | Scope guillotine | 10 min |
| Dread / avoidance | Click test | 2 min |

## Blank-page exercises

### Ugly sentence drill
1. Ask the user to write the single worst, most clichéd version of their
   post's main point. Encourage genuinely bad writing.
2. Ask: "What's wrong with that sentence?" Their answer is the seed of the
   real one — they now write *their* version, not you.
3. Rule: you never write either version. You only react.

### Interview dump
1. Play a curious junior engineer. Ask 5 rapid questions about the topic
   ("Why does G1 pause here?", "What broke first in production?").
2. Have the user answer each in 1–2 typed sentences, casually, as if in chat.
3. Point out that their answers just became the post's skeleton — they
   rearrange and expand from there.

### 200 bad words
- Set the explicit target: 200 words, quality irrelevant, no deleting.
- When done, do NOT review quality. Ask only: "Which sentence surprised you?"
  That sentence anchors the next session.

## Mid-draft stall exercises

### Casual-sentence probe
1. Ask: "Explain the stuck section to me in one sentence, like you're
   telling a coworker at lunch."
2. Compare their sentence to the stuck paragraph. Ask why the written
   version is harder than the spoken one — the answer is the diagnosis
   (jargon armor, missing example, unclear audience).
3. They rewrite starting from the casual sentence.

### Rubber-duck the gap (research problem, not writing problem)
Use when the stall hides a knowledge gap. Have the user:
1. State the claim they want to make.
2. List what they'd need to verify it (a benchmark, a doc, a prototype).
3. Pick the cheapest verification and go do it. Writing pauses; this is
   sanctioned, not procrastination. Set a return point: "come back with
   one number or one counterexample."

### Section veto test
Ask three questions about the stuck section:
1. Does the post's one-sentence takeaway survive without this section?
2. Is this section here because it's needed, or because it was hard to
   learn and feels wasteful to cut (sunk cost)?
3. If cut, does any other section break?
Two or more "cut" answers → delete it or demote it to an appendix.

## Perfectionism-loop exercises

### No-backspace sprint
1. 25-minute timer. Only forward typing counts; fixing typos is banned.
2. Weak lines get `[TK]` and the user keeps moving.
3. After the sprint, they may edit — but only after the section is complete.
4. If they cheat and edit mid-sprint, call it out; the loop *is* the habit
   being trained away.

### TK sweep
For a draft littered with `[TK]` markers:
1. List all markers without judging them.
2. Sort: factual `[TK]` (needs verification) vs stylistic `[TK]` (needs a
   better phrase).
3. Factual ones get the rubber-duck treatment; stylistic ones get a 2-minute
   budget each — unsolved after 2 minutes, the plain version ships.

## Dread / avoidance exercises

### Scope guillotine
1. Ask: "What's the smallest version of this post that would still be true
   and useful?"
2. Keep cutting until the answer can be written in one sitting (a TIL note,
   one config snippet + 5 sentences).
3. Ship that. A deep dive that never ships teaches nothing; the small post
   often becomes the outline for the big one.

### Click test
1. Ask: "If someone else published this exact post, would you click it?"
2. If no — the block is signal, not malfunction. Options: find the angle
   that *would* make them click (usually the failure story or the number,
   not the tutorial), or kill the post without guilt.
3. Killing a post is a valid outcome. Say so explicitly.

## Freewriting prompts (fallback for any block type)

When diagnosis is unclear, offer one prompt, 10 minutes, no stopping:
- "The thing nobody tells you about [topic] is..."
- "I was wrong about [topic] when..."
- "If [topic] breaks in production at 3am, the first thing you check is..."
- "The docs say X. What actually happens is..."

The output is raw material, not prose. After the timer, ask the user to
underline (or tell you) the one line worth keeping.
