# TDD handoff

Use this reference only when the person explicitly asks for TDD, test-first development, red-green-refactor, or integration tests.

1. Activate the installed `tdd` skill and follow its workflow and references. It defines the red → green loop, test quality, placement, and mocking guidance.
2. Keep the repository conventions learned through `/dev-companion init` and the minimal-coding scope: write only tests needed for requested behavior, then the smallest implementation that passes them.
3. Do not activate TDD automatically for ordinary coding tasks. Implement first and run relevant checks unless the person explicitly requests a test-first workflow.
4. If the `tdd` skill is unavailable, say so briefly and ask whether to follow a basic red → green workflow instead of silently imposing it.
