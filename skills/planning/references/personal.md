# Personal / Task Plans

For side projects, life goals, multi-step errands, home projects, learning goals — anything one person plans for themselves. The goal is a plan that reduces the work to a series of small, startable actions, so the user never stares at a big blob of a goal wondering where to begin.

## 1. Interview essentials

Ask only what matters:

- **The goal** — what does done look like? ("A working landing page" not "something on the internet")
- **The deadline or time budget** — is this "by Friday" or "an hour a day" or "whenever"?
- **What already exists** — prior attempts, half-built things, materials on hand
- **Blockers** — things outside their control (waiting on someone, on money, on a decision)

## 2. Break it down

- Cut the work into tasks small enough to **finish in one sitting** (a few hours max). A task that can't be started in the next five minutes is too big — keep splitting.
- **Mark priorities**: P0 (must happen), P1 (should happen), P2 (nice if time). This lets the user cut scope without re-planning when life happens.
- Order by dependency ("write the outline" before "draft the chapters"), but don't overthink it — personal plans benefit from a sensible order, not a dependency graph.

## 3. Keep it human

- **Time estimates** with a built-in buffer — personal estimates are optimistic; add 30–50% if asked for a schedule.
- **One next action** — end the plan by naming the single first step, so the user knows exactly what to do when they look at the plan tomorrow.
- **Review points** for anything longer than a week ("check in after step 4: is the scope still right?").
- No jargon. No story points, no velocity. This is a plan for a person, not a board.

## 4. Output format

Use the general task anatomy (action / what's involved / verify / time) with priorities:

```markdown
# Plan: <goal>
Deadline: <date or "none"> | Priority: <P0/P1/P2>

## Done looks like
<one or two sentences>

## Tasks
- [ ] **P0** <action> — <what's involved> (~<time>)
      Verify: <how you know it's done>
- [ ] **P1** <action> — <what's involved> (~<time>)
      Verify: <how you know it's done>
...
## Blockers / open questions
- <waiting on X>
```

## Anti-patterns specific to personal plans

- Corporate boilerplate — a personal plan with velocity metrics or stakeholder sections is noise. Keep it lean.
- Tasks without a clear start — "plan the wedding" isn't a task; "book the venue (call the three shortlisted venues, compare quotes)" is.
- No priorities — without P0/P1/P2 the user can't decide what to drop when time runs short, which is exactly when they'll need the plan.
- Perfectionism-inducing detail — a personal plan should make starting *easier*, not feel like homework. When in doubt, cut a section.
